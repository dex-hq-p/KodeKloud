Phần A – Cluster Architecture, Installation & Configuration (25 điểm)
Câu 1 – RBAC (5 điểm)

Namespace backend đã tồn tại.

Yêu cầu:
1. Tạo ServiceAccount tên backend-developer trong namespace backend.
2. Tạo Role tên pod-manager, cho phép:
   - get, list, watch, create, delete trên Pods.
   - get, list, watch trên ConfigMaps.
3. Bind Role này cho ServiceAccount.
4. Đảm bảo ServiceAccount không có quyền tạo Deployment.
5. Verify bằng kubectl auth can-i.
Câu 2 – Cluster Upgrade (7 điểm)

Cluster hiện đang chạy Kubernetes v1.36.x.

Yêu cầu:
1. Upgrade control plane lên v1.37.x.
2. Upgrade kubelet và kubectl trên control plane.
3. Drain worker node worker-01.
4. Upgrade kubelet trên worker.
5. Uncordon worker sau khi hoàn thành.
Không được làm mất workload đang chạy trên cluster.

Câu 3 – Helm & Kustomize (5 điểm)

Namespace monitoring đã tồn tại.

Yêu cầu:
1. Cài đặt một Helm chart vào namespace monitoring.
2. Đặt release name là node-exporter.
3. Override giá trị image tag theo yêu cầu 1.9.1.
4. Tạo Kustomize overlay production để thay đổi replica của Deployment api-server từ 2 lên 4.
5. Apply overlay lên cluster.
Câu 4 – ETCD Backup (8 điểm)

Trên control plane:
1. Tạo snapshot của etcd tại /opt/backup/etcd-snapshot.db.
2. Đảm bảo snapshot được tạo thành công.
3. Verify snapshot bằng công cụ phù hợp.
4. Ghi lại kích thước file và trạng thái snapshot.
Phần B – Workloads & Scheduling (15 điểm)
Câu 5 – Deployment & Rollback (4 điểm)

Trong namespace production:
1. Tạo Deployment payment-api với 3 replicas.
2. Sử dụng image nginx:1.27.
3. Cập nhật image thành nginx:1.28.
4. Thực hiện rollback về revision trước đó.
5. Verify image sau rollback.
Câu 6 – Scheduling (4 điểm)

Cluster có node worker-02 với label:
disk: ssd
environment: production


Yêu cầu:
1. Tạo Pod scheduled-app.
2. Chỉ cho phép Pod chạy trên node có disk=ssd.
3. Pod phải có toleration phù hợp với taint dedicated=backend:NoSchedule.
4. Đảm bảo Pod chạy thành công.
Câu 7 – ConfigMap & Secret (3 điểm)

Tạo:
- ConfigMap app-config với APP_ENV=production.
- Secret db-secret chứa username và password.
- Deployment config-app sử dụng ConfigMap dưới dạng environment variables và Secret dưới dạng mounted volume.
Không được hardcode username/password trong Deployment.

Câu 8 – Autoscaling (4 điểm)

Deployment web-app có 2 replicas.

Yêu cầu:
1. Tạo HPA tên web-app-hpa.
2. CPU utilization target là 60%.
3. Minimum replicas: 2.
4. Maximum replicas: 10.
5. Đảm bảo Deployment có CPU requests phù hợp để HPA hoạt động.
Phần C – Services & Networking (20 điểm)
Câu 9 – Service & Endpoint (4 điểm)

Namespace frontend có Deployment web với 3 replicas.

Yêu cầu:
1. Expose Deployment qua Service web-service.
2. Service type là NodePort.
3. Service port 80, targetPort 8080, NodePort 30080.
4. Đảm bảo Service có đủ endpoints.
Câu 10 – NetworkPolicy (5 điểm)

Namespace secure có:
- Pod frontend với label app=frontend.
- Pod backend với label app=backend.
- Pod database với label app=database.
Yêu cầu:
1. Chỉ cho phép frontend truy cập backend qua TCP port 8080.
2. Chỉ cho phép backend truy cập database qua TCP port 5432.
3. Database không được nhận traffic trực tiếp từ frontend.
4. Các traffic khác vào backend và database phải bị chặn.
Giả định CNI hỗ trợ NetworkPolicy.

Câu 11 – Ingress / Gateway API (6 điểm)

Namespace gateway-demo đã tồn tại.

Yêu cầu:
1. Cấu hình Gateway API để expose ứng dụng shop-service.
2. Gateway listener sử dụng HTTP port 80.
3. Tạo HTTPRoute cho hostname shop.example.com.
4. Request tới /api phải được forward tới shop-service port 8080.
5. Verify route đã được accepted và programmed.
Giả định Gateway API CRDs và Gateway Controller đã được cài đặt.

Câu 12 – CoreDNS (5 điểm)

Pod client trong namespace frontend không resolve được DNS của Service api-service trong namespace backend.

Yêu cầu:
1. Kiểm tra CoreDNS.
2. Xác định nguyên nhân.
3. Khắc phục sự cố.
4. Verify DNS bằng nslookup hoặc busybox.
Phần D – Storage (10 điểm)
Câu 13 – PV / PVC (5 điểm)

Tạo PersistentVolume với thông số:
- Capacity: 2Gi.
- AccessMode: ReadWriteOnce.
- ReclaimPolicy: Retain.
- StorageClassName: manual.
- HostPath: /mnt/data/app.
Sau đó:
1. Tạo PVC app-pvc yêu cầu 1Gi.
2. Bind PVC vào PV.
3. Tạo Pod storage-app mount PVC tại /data.
4. Verify dữ liệu có thể ghi và đọc.
Câu 14 – StorageClass (5 điểm)

Một StorageClass fast-storage đã tồn tại.

Yêu cầu:
1. Cấu hình StorageClass với volumeBindingMode: WaitForFirstConsumer.
2. ReclaimPolicy là Delete.
3. Tạo PVC sử dụng StorageClass.
4. Tạo Pod sử dụng PVC.
5. Verify PVC được provision và bind thành công.
Giả định cluster có CSI provisioner tương thích.
Phần E – Troubleshooting (30 điểm)
Câu 15 – Cluster & Application Troubleshooting (30 điểm)

Đây là bài tổng hợp nhiều lỗi độc lập. Mỗi lỗi có 6 điểm.

15.1 – Pod CrashLoopBackOff (6 điểm)

Pod order-service liên tục CrashLoopBackOff.

Yêu cầu:
- Xác định nguyên nhân từ logs và describe.
- Khắc phục lỗi.
- Đảm bảo Pod Running.
15.2 – Node NotReady (6 điểm)

Node worker-03 chuyển sang trạng thái NotReady.

Yêu cầu:
- Kiểm tra tình trạng node.
- Kiểm tra kubelet.
- Kiểm tra container runtime.
- Khắc phục và đưa node về Ready.
15.3 – Service không hoạt động (6 điểm)

Service inventory-service tồn tại nhưng không thể truy cập từ Pod khác.

Yêu cầu:
- Kiểm tra selector.
- Kiểm tra EndpointSlice.
- Kiểm tra port và targetPort.
- Khắc phục để Service hoạt động.
15.4 – Control Plane Troubleshooting (6 điểm)

kube-apiserver trên control plane bị restart liên tục.

Yêu cầu:
- Kiểm tra static Pod manifest.
- Kiểm tra logs.
- Xác định lỗi cấu hình.
- Khôi phục API Server.
15.5 – Resource Troubleshooting (6 điểm)

Namespace production có Pod bị OOMKilled liên tục.

Yêu cầu:
- Xác định nguyên nhân.
- Kiểm tra resource requests và limits.
- Điều chỉnh cấu hình để ứng dụng hoạt động ổn định.
